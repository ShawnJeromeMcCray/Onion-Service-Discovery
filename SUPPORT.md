# Getting help

Start with the [quickstart](docs/getting-started/quickstart.md),
[installation guide](docs/getting-started/installation.md) and
[troubleshooting](docs/getting-started/troubleshooting.md).
The current channel is a development preview; no production support SLA exists.

For ordinary bugs, open a [GitHub issue](https://github.com/ShawnJeromeMcCray/Onion-Service-Discovery/issues/new/choose)
with the source commit, operating system, PHP/Node/Tor versions, intended role,
exact error code, reproduction steps, expected result and observed result.
Say whether the problem involves synthetic demo data, a controlled lab or real
operator infrastructure. Include only the smallest sanitized relevant output.

Do not include private keys, passphrases, tokens, private backups, pin exports,
search queries/history or private paths. Redact operator-specific addresses when
they are not necessary. A Node address being public does not make unrelated
local state appropriate to share. Security-sensitive reports belong through the
[security reporting policy](SECURITY.md), not ordinary public issues.

Feature/protocol suggestions should describe the user problem and the requirement
or decision they affect. See [contributing](CONTRIBUTING.md); new wire formats
require review, exact-byte tests and explicit limits.
