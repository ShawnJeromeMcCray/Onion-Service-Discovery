# ADR 004: durable journal commit before publishing filesystem HEAD

Status: IMPLEMENTED DEVELOPMENT STORAGE FIX; no production or physical power-loss approval.

The current storage contract requires PREPARE without COMMIT to remain
uncommitted. Format 1 instead treated an advanced HEAD as authoritative and
could synthesize COMMIT during recovery. A failed COMMIT write after HEAD
therefore exposed a transaction without the required durable commit record.

Format 2 writes immutable objects/checkpoint, fsyncs PREPARE, fsyncs COMMIT,
then atomically replaces and fsyncs HEAD. Recovery publishes a committed
successor only after validating its exact predecessor, generation and
checkpoint. It never promotes PREPARE alone. Read-only access refuses pending
recovery and performs no writes.

Existing format-1 stores require explicit `storage:migrate filesystem PATH`.
Migration takes the writer lock, validates all retained immutable objects
before any recovery, preserves transactions accepted by the original format-1
rules, finishes historical recovery, then atomically changes the native format
marker. It does not rewrite signed records, cursors or the logical storage
schema. A second invocation is idempotent. Process interruption before or after
the marker change resumes without losing already accepted history.

Three fixtures were generated by the actual earlier implementation at commit
`04c04189b500132ad4807087a2c501f04c1dd55d`: clean state, PREPARE with advanced
HEAD, and PREPARE with unchanged HEAD. Migration, record/cursor preservation,
corrupt-object rejection, process interruption and real tmpfs ENOSPC are tested.
This is controlled process/filesystem evidence, not hardware power-loss proof.

Protocol validation changes are a separate compatibility boundary. Native
format migration cannot make historical signed records valid under a changed
category/language profile; that transition remains unresolved in PCP-001.
